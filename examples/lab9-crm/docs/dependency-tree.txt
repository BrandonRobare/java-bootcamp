# Dependency tree — Lab 9 (customer-service)

Captured with `mvn dependency:tree` (no `-q` — the tree IS the output).

## Direct vs transitive

Decided by **indentation**, not by the symbol. Anything flush against the root
line is direct; everything indented under it arrived uninvited.

| Dependency | Direct or transitive? |
| ---------- | --------------------- |
| `org.springframework:spring-context` | **Direct** — declared in `pom.xml` |
| `org.junit.jupiter:junit-jupiter` | **Direct** — declared in `pom.xml`, `test` scope |
| everything indented beneath those two | Transitive |

One declared Spring dependency pulls in seven compile-scope artifacts, including
`io.micrometer:micrometer-observation` — a metrics library from a different vendor,
now on the production classpath. JUnit pulls eight, all `:test`, none of which ship.
That contrast is the whole argument for scopes.

## Why `junit-jupiter` must stay `test`

On the default `compile` scope, JUnit lands on the production compile classpath, so
production code can `import org.junit.jupiter.api...` and still build. It also becomes a
transitive dependency inherited by anyone who depends on this artifact.

It does **not** get packaged into `customer-service.jar` — a plain JAR contains only its
own classes, never its dependencies, so scope cannot change what is inside it. Verified
in `failure-experiments.md` #3: with the scope removed the tree read `:compile`, but
`jar tf` still found zero `org/junit` entries and the artifact stayed ~8.5 KB. The
"ships to customers" failure needs a fat JAR (shade, assembly, or a Boot repackage).

The real proof is the compiler. The same `Main.java` referencing a JUnit type builds
clean on `compile` scope and fails on `test` scope with `package org.junit.jupiter.api
does not exist`. Scope is an enforced boundary, not documentation.

## Symbols

- `+- org.springframework:spring-beans:jar:6.2.3:compile` — a `+-` line: more siblings
  follow it under `spring-context` (`spring-core`, `spring-expression`, `micrometer`).
- `\- io.micrometer:micrometer-commons:jar:1.14.4:compile` — a `\-` line and the
  deepest node in the Spring branch: nothing follows it under its parent.

`\-` means *last sibling at this level* — a position, not a depth.
